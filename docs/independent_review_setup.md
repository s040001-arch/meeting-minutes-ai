# 独立レビュー体制: モデル選定と指示文（2026-08-07）

## なぜ別系統モデルか

このパイプラインは検出も修正も検証もすべて Anthropic 系（Claude）で行っている。
同系統モデルは盲点が相関するため、「作った本人が見逃すものはレビュー役も見逃す」
構造になりやすい。実際、楽天ジョブの「第2希望→第1希望」書き換えは Claude の
検証2系統をすり抜け、ユーザーが別系統AIに読ませて初めて指摘された。

対策は2层:
1. **決定論ガード**（本リポジトリに実装済み: `fact_token_audit.py` の横断検問、
   `section_consistency_check.py`）— モデルに依存しない検問。
2. **別系統モデルによる独立監査** — 以下の使い分け。

## モデル使い分け（Cursor で利用可能なもの）

| 用途 | 推奨モデル | 理由 |
|---|---|---|
| 構造監査（設計の穴・ガード非対称の発見） | GPT-5.6 (Sol/Terra) | 別系統で盲点が非相関。コード読解と「すり抜け例の構成」が得意 |
| 初見読者監査（成果物の違和感検出） | GPT-5.6 または Grok 4.5 | 生成に関与していないモデルほど違和感に敏感 |
| アーキテクチャ相談・修正の実装 | Claude Opus 5 (thinking) / Fable | 実装文脈の理解と修正の精度 |

運用: 大きな機能追加や事故のあとに、下の指示文①を GPT-5.6 のサブエージェント
またはチャットに貼って実行する。成果物チェックは②を議事録本文と一緒に貼る。

## 指示文テンプレート

### ① 構造監査（コードベース向け）

```
あなたは議事録自動生成パイプラインの独立監査人です。個別のバグ修正ではなく、
「ミスが構造的に発生し続ける設計」を見つけることが任務です。

対象リポジトリ: meeting-minutes-ai（テキストを LLM で多段修正するパイプライン）

次の観点で調査し、発見ごとに「該当ファイル:行 / すり抜ける具体例 / 修正方針」を
重大度順に報告してください。

1. ガードの非対称性: 本文テキストを書き換える経路をすべて列挙し、各経路の
   安全ガード（数値・人名・固有名詞・意味保存の検証）の有無と実装差を表にする。
   ある経路にだけガードがない、または実装が微妙に違う箇所は事故の温床。
2. 黙殺分岐: 問題を検出したのに、ログにも質問キューにも残らず捨てられる分岐。
3. 許可リスト方式の穴: 正規表現の単位リストや列挙型のバリデーションを探し、
   リスト外の入力ですり抜ける具体的な反例を構成する。
4. 生成物間の整合性: 要約・決定事項・残論点・発言録が互いに矛盾しても
   検出されない箇所。「決定」と書く基準が検証されているか。
5. 検証対象のズレ: 「最終検証」がユーザーが実際に見る最終成果物
   （Google Doc の全文）を対象にしているか。中間生成物だけ見ていないか。
6. 状態の一貫性: 同じ事実（確定した修正・回答）が複数ファイルに保存される場合、
   片方だけ更新されて食い違う経路がないか。

見つからなかった観点も「調査したが問題なし（根拠）」と明記してください。
```

### ② 初見読者監査（成果物向け）

```
あなたはこの会議に出ていない初見の読者です。以下の議事録を読み、
「読んでいて意味が取れない・引っかかる」箇所をすべて挙げてください。

ルール:
- 修正案は不要。違和感の指摘だけに集中する（修正を考えると保守的になるため）。
- 網羅性を重視: 前半で違和感を挙げ尽くしても、後半も同じ密度で読む。
- 種類を分類する: (a)意味不明な語・崩れ (b)文として繋がらない
  (c)セクション間の矛盾（決定事項と残論点、要約と本文など）
  (d)話の流れが飛ぶ (e)人名・数値の不整合
- 各指摘に本文の該当箇所を引用で付ける。

最後に「この議事録を仕事で受け取ったら困る度」を10点満点で採点し、
減点理由を1行ずつ書いてください。
```

### ③ 差分監査（処理前後の比較向け）

```
以下は同じ議事録の処理前と処理後です。処理は「読みやすくする」ことが目的で、
事実・数値・人名・固有名詞・主張の内容を変えてはいけません。

処理前と処理後を突き合わせ、次を報告してください:
1. 事実が変わった箇所（数値・人名・日付・条件・主語の変化）
2. 意味が変わった箇所（断定⇔推測、肯定⇔否定、主体の入れ替わり）
3. 情報が消えた箇所（発言の削除で文脈が失われたもの)
4. 処理後に新しく現れた、処理前に根拠のない情報

各項目、引用ペア（前→後）で示してください。「問題なし」の場合もその旨を明記。
```

## パイプラインへの自動組み込み（将来オプション）

②③をパイプライン内で自動実行するには OpenAI/Google の API キーを Railway に
追加し、`_verify_full_text` の2系統目を別系統モデルに差し替える。
現状は決定論ガード＋Claude 検証＋人手での別系統レビューで運用する。
